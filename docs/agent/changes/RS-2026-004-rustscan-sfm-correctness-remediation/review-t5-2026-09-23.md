## Findings

### P1 — Validate derived point errors before committing Reconstruction

Location: `rustscan-sfm/src/ba/ceres_problem.rs:449-464`.

`prepare_write_back` checks parameter values, but `try_write_back_solution`
mutates the live model before `refresh_point_errors` executes. Finite, valid
camera parameters do not ensure finite derived point errors. An independent
probe through the real solver/write-back path used the existing injection
seam to set focal length to `3e38` (finite in both f64 and f32), with a fixed
point `[4, 0, 2]` and finite observations. The result was
`report.is_solution_usable() == true`, committed focal `3e38`, and point error
`inf`. The rejection-and-unchanged-state assertion failed (exit 101).

Required action: include refreshed point errors and derived image/frame/sensor
poses in the candidate state. Validate the final values, including narrowing
and accumulation, before a single live-state commit; reject the entire update
on failure. Keep usable NoConvergence semantics. The injected large value
exercises validation deterministically; this does not claim ordinary Ceres
runs commonly produce such a focal value.

Evidence: `artifacts/runs/t5-independent-review/finite-error-probe.rs.txt` and
`finite-error-probe.log` in this worktree.

### P2 — Unusable global BA still falls through to destructive filtering

Location: `rustscan-sfm/src/sfm/global_mapper.rs:674-678`, with the remaining
mutation at lines 720-728.

The rejection branch breaks only the refinement loop, then executes the final
track filter. This can remove existing points and observations despite BA
being rejected. Duplicating the new failure regression and changing only
`filter_min_track_length` from 1 to 3 deletes its two-view point and fails the
existing assertion `unusable BA must not clear structure during the stopped
round` (exit 101). The original permissive thresholds hide this path.

Required action: distinguish normal loop completion from BA failure and skip
post-BA filtering after an unusable/absent/cancelled result. Preserve already
accepted work before the failed BA boundary; this finding does not demand
rollback of the initial triangulation pass or earlier successful rounds.
Add a regression with a point that the final filter would actually remove.

Evidence: `artifacts/runs/t5-independent-review/global-abort-probe.rs.txt` and
`global-abort-probe.log` in this worktree.

### P2 — Test overrides are exposed in production APIs and solver execution

Location: `rustscan-sfm/src/ba/mod.rs:229-245`,
`rustscan-sfm/src/ba/ceres_problem.rs:407-425`, and
`rustscan-sfm/src/sfm/global_mapper.rs:118-119`.

`BaCommitTestOverride` and the options fields are public and unconditionally
compiled. Production callers can override Ceres usability/termination and
replace optimized camera parameters. A comment requiring None does not keep
this test seam out of production, and the new required public struct fields
also impose source compatibility costs unrelated to the runtime feature.

Required action: use a private test seam or cfg(test)-only injection, including
all forwarding and mutation logic. Keep production options free of failure
injection controls. Reduce commit-decision helper visibility unless an actual
external caller needs it.
