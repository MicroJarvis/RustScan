## Remaining P1 — Derived pose/projection failure can pass candidate validation

Locations: `rustscan-sfm/src/ba/ceres_problem.rs:1804-1807` and `1734-1736`.

After apply_prepared_write_back composes frame and sensor poses, the candidate
is not checked for finite/valid final poses. refresh_point_errors_checked
then treats every project_point(None) as a skippable observation. This includes
non-finite arithmetic, not only intentionally unsupported geometry. If no
observation survives, a finite old point.error is retained and the candidate
returns Ok. With a usable solver summary, it is eligible for installation.

Independent deterministic probe of the production build_validated_candidate
helper: identity rotations, finite frame translation x=3e38, finite sensor
translation x=3e38, and a point observed by that sensor. Each translation
individually fits f32, but their composition overflows. The helper returns Ok
with image pose translation `[inf, 0, 0]` and unchanged point.error=2.5. The
assertion requiring rejection fails (exit 101). This exercises the candidate
validation boundary; it does not claim a naturally occurring Ceres solve
produced these extreme parameters.

Required action:

1. Validate resulting image, frame and sensor pose values after composition
   and normalization, including finite translations and valid rotations,
   before installing the candidate. Parameter-level checks are insufficient.
2. Distinguish expected finite geometric non-projectability (for example,
   behind-camera handling under the existing policy) from non-finite camera
   coordinates or projection arithmetic. Reject numerical failures; do not
   silently keep the old point error to hide them. Do not indiscriminately
   reject every None if that would change the existing geometric policy.
3. Add regressions for finite operands producing non-finite derived poses and
   projection arithmetic returning None due to non-finite results. Assert
   rejection and bitwise preservation of the live model. Exercise the real
   candidate/commit path, including a usable termination state.
4. Keep the now-fixed failure-filtering and production-API behavior intact.
